# 实战6：SSE流式打字机交互与文案管理

刘嘉略 · 0120251050 · 2026-10-31

在已完成的实战5工程上增加POST /api/copy/stream、GET /api/assets、DELETE /api/assets/:id，保留原有非流式接口。

后端通过streamChat异步生成器请求stream:true与include_usage，增量解码UTF-8，按空行解析SSE；处理CRLF、跨块中文、多行data、心跳和不完整尾帧。只有收到上游[DONE]才视为正常结束，截断、过滤和异常均不保存。未知Token保留null。

参数、商品识别状态及语言渠道在开启SSE前校验，失败返回普通JSON。通过flushHeaders立即发送text/event-stream、no-cache/no-transform、X-Accel-Buffering:no；delta实时转发，done包含保存ID、最终遮蔽文案、warnings及usage。模型格式/事实检查失败最多重新生成一次，delta的reset:true通知前端清空上一版草稿，最多两次模型调用。

使用res.on('close')联动AbortController，而非req.on('close')。停止、离开页面或浏览器断开会中断上游；半份草稿不保存。生成完成且质量检查通过才保存MarketingAsset，保存成功后发done。

前端fetch POST读取ReadableStream，复用分块解析器，支持停止、闪烁光标和错误提示。marked生成的HTML交给DOMPurify净化。历史来自MongoDB，支持查看、复制及二次确认删除；复制失败给出手动复制提示。流式过程中内容是未审核草稿，完成时才进行最终敏感词遮蔽，不能直接当作发布稿。
